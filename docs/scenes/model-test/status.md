# 씬 3 — 모델 테스트 (model-test)

```
web/?scene=model-test        # 기본 씬 — 아무것도 안 붙여도 여기가 뜬다
```

아무것도 없는 바닥과 하늘, 그리고 한가운데 **1m 나무 상자 하나.**
형태를 하나씩 만들어 보는 자리다 — **브라우저를 그냥 켜면 여기가 뜬다.**

## 1. 무엇이 있나

| | |
|---|---|
| 바닥 | 400m 정사각 평면, 중립 회색 (`0x8d8f92`, 거칠기 0.95) |
| 하늘 | 그라디언트 돔 반경 500m + 안개 45~190m |
| 광원 | 반구광 0.45 · 주광 2.2(그림자) · 채움 0.35 |
| 물건 | 나무 상자 **정확히 1.0m** — 원점에 앉아 있다 |

씬 이름(`meta.name` = '모델 테스트')이 탭 제목·로딩 화면·좌측 하단 HUD 셋을
한꺼번에 채운다. 예전에는 셋 다 `index.html` 에 1번 씬 이름이 박혀 있었다.

처음 실측(상자만): 삼각형 1,486 · 텍스처 4장 4MB · 재질 3 · 빌드 0.1초.

캐릭터가 들어온 뒤 (2026-08-02):

```
삼각형 61,380 · 텍스처 6장 9.4MB · 재질 13 · 빌드 146ms · 경고 0
캐릭터 부품 145 (아웃라인 껍질 64) · 스킨드 6 · 본 30 · 스프링 2줄
```

## 2. 왜 상자인가

텅 빈 씬은 켜도 켜졌는지 알 수 없다. 1m 짜리 상자가 하나 서 있으면 셋이
한눈에 확인된다.

- 씬이 실제로 빌드됐는가
- 스케일이 맞는가 (**1m = 1유닛**)
- 광원과 그림자가 도는가

앞으로 여기 세울 것의 크기도 이 상자에 대고 재면 된다. 크기를 바꾸면
그 기준이 사라지므로 `CRATE = 1.0` 은 딱 떨어지는 값으로 둔다.

## 3. 만들면서 고친 것

### 3.1 안개로 가까운 것을 가리려 했다

바닥을 120m 로 두고 안개(55~230m)로 끝을 지우려 했는데, 평면 모서리가
하늘을 자르며 그대로 드러났다. 모서리까지 거리가 60m 인데 그 지점의 안개는
**3%** 였다.

> **안개는 먼 것을 지우는 물건이지 가까운 것을 가리는 물건이 아니다.**
> 완전히 잠기는 거리까지 땅을 넓히는 것이 순서다.

바닥 400m · 안개 45~190m 로 바꿨다. 모서리(200m)는 하늘색에 완전히 잠긴다.

### 3.2 광원을 카메라 쪽에 뒀더니 상자가 납작했다

주광을 `(9, 12, 7)` 에 뒀다. 카메라가 `+X+Z` 에서 보므로 눈에 드는 두 면
(`+X`·`+Z`)이 **둘 다 정면광을 받아** 밝기가 같아졌다. 모서리가 사라져
나무 무늬를 입힌 사각형처럼 보였고, 그림자도 상자 뒤로 숨었다.

`(-6, 9.5, 7)` 로 옮겼다 — 광원을 `−X+Z` 에 두면 `+Z` 만 밝고 `+X` 는
그늘이 되어 모서리가 선다. 그림자도 오른쪽으로 나와 보인다.

### 3.3 샷 파일 이름이 씬마다 겹쳤다 — 공용 코드 결함

씬을 셋째로 늘리자 드러났다. 샷 파일 접두사를 정하는 코드가
`main.js` 와 `tools/verify.mjs` **두 곳에** 따로 적혀 있었다.

```js
const tag = scene === 'night-city' ? 'nc_' : '';   // 양쪽에 각각
```

씬이 둘일 때는 우연히 맞았지만, 무대의 `wide` 뷰가 공터의 `wide` 와
**같은 파일**(`wide.png`)을 덮어쓰게 된다. 기준선이 조용히 지워지고
회귀 검증은 계속 "일치" 라고 말했을 것이다.

접두사를 `views.json` 의 `_tag` 로 옮겼다 (`""` · `mt_` · `nc_`).
카메라 설정과 마찬가지로 **유일한 출처는 views.json 하나**다.
자세한 것은 [../../lessons.md](../../lessons.md) 결합 대장.

### 3.4 어느 씬을 띄워도 이름이 '주택가 공터' 였다

`index.html` 에 1번 씬 이름이 **세 군데** 박혀 있었다 — 탭 제목 ·
로딩 화면 · 좌측 하단 HUD. 도시를 띄워도 화면 왼쪽 아래에는 공터라고
적혀 있었고, 씬이 셋이 되고서야 눈에 띄었다.

`main.js` 가 셋 다 `SCENE.meta.name` 으로 덮는다. **씬 이름의 출처는
`meta.name` 하나다.** HTML 에 남은 값은 스크립트가 돌기 전 한순간만
보이는 것이라 씬 이름이 아닌 '절차적 생성' 으로 바꿨다.

덤으로 HUD 통계 줄 맨 앞에도 씬 이름이 또 들어가 있어서 두 줄에 같은
이름이 겹쳤다. 통계에서 뺐다.

## 4. 서브컬처 아바타를 코드로 만들어 봤다 (2026-08-02)

사용자 지시: *"니가 해봐 한번 / 아예 똑같이는 아니더라도 비슷하게라도 만들어봐"*

"이 방식으로는 안 된다" 고 답한 뒤, 실제로 어디까지 가는지 재 보려고 지었다.
결과는 3장의 스크린샷과 아래 기록이다.

```
삼각형 44,228 · 텍스처 6장 9.4MB · 재질 13 · 메시 106 · 빌드 137ms
```

### 4.1 무엇으로 만들었나

| 파일 | 무엇 |
|---|---|
| `surface.js` | **로프트**(높이별 초타원 단면)와 **스윕**(경로 + 단면). 사람 몸은 거의 다 이 둘이다 |
| `toon.js` | 툰 마스터(단계 램프) + **역법선 껍질 아웃라인**. 선은 셰이더가 아니라 지오메트리다 |
| `paint.js` | 캔버스 2D 경로로 **그리는** 텍스처. `bake()` 픽셀 루프로는 눈매를 못 그린다 |
| `face.js` | 얼굴 한 장 — 눈매·홍채·눈썹·코·입·홍조 |
| `head.js` | 머리·목·뾰족귀. 정면을 눌러 평평하게 |
| `hair.js` | 껍질·앞머리·옆머리·뒷머리·**땋은 머리**·안테나·뿔 |
| `body.js` | 몸통·팔다리·의상 |

### 4.2 코드가 이긴 것 — 땋은 머리

세 가닥이 축을 돌며 내려간다.

```
P(t) + (cos θ, 0, sin θ) · r(t),   θ = 2π·turns·t + i·(2π/3)
```

꼬임 수는 길이와 굵기에서 유도한다 — 굵기를 바꾸면 꼬임이 따라온다.
손으로 만들면 제일 고통스러운 형태이고, 코드로는 숫자 하나로 조절된다.
**이 캐릭터에서 면적이 제일 큰 것이기도 하다.**

### 4.3 코드가 진 것 — 얼굴

얼굴은 형태가 아니라 **그림**이라 캔버스 경로로 그렸다. 눈 하나가
눈구멍 곡선 + 홍채 그라디언트 + 방사 결 + 테두리 + 동공 + 하이라이트 둘 +
위 눈매 + 속눈썹 둘 + 쌍꺼풀 + 아래 눈매 = **열한 겹**이다.

되기는 된다. 그런데 값 하나 고칠 때마다 새로고침해야 하고, 붓으로 5초에
할 일을 30분 한다. **도구가 없는 게 아니라 되먹임 고리가 그림에 안 맞는다.**

### 4.4 고친 것 여섯

| | 증상 | 원인 |
|---|---|---|
| 1 | 눈을 관통하는 가시 | `taperStroke` 의 되돌아오는 변이 `moveTo` 로 새 서브패스가 됐다. 굵기가 변하는 선은 **한 경로**여야 한다 |
| 2 | 팔이 2m 널빤지가 되어 바닥까지 | `ringsFrom` 이 y **오름차순**을 전제하는데 팔은 관절에서 아래로 적어 내림차순이었다. 마지막 구간으로 외삽했다 |
| 3 | 얼굴이 흰 가면 | 머리카락 껍질 밑단이 눈보다 아래였다. 껍질은 정수리만, 이마는 앞머리, 뒤통수는 뒷머리 |
| 4 | 앞머리가 두개골 안 | 곧은 칼날을 회전시켰다. **머리카락은 두피를 따라 붙어 내려온다** — 링마다 깊이를 따로 줘야 한다 |
| 5 | 은발이 흑발 | 아웃라인 껍질이 땋은 머리의 **홈을 전부 메웠다.** 선은 실루엣을 살리는 물건이지 모든 부품에 두르는 물건이 아니다 |
| 6 | 눈이 실사 비율 | 눈 반폭 0.118 -> 0.148, 홍채가 눈꺼풀에 **잘리는** 크기로. 흰자가 넓으면 그 순간 무섭다 |

### 4.5 2차 — "최선이야?" 를 듣고 더 간 것

첫 판은 6번 돌리고 멈춘 것이지 최선이 아니었다. 남아 있던 것을 더 했다.

| | 무엇 | 왜 |
|---|---|---|
| **손가락** | 주걱 하나 -> 손바닥 + 손가락 넷 + 엄지 | 전신 뷰에서 "저건 뭐지" 로 읽히던 유일한 부위. 가는 관 다섯이라 삼각형 1,400개 |
| **림 라이트** | 툰 마스터에 셰이더 주입 | 단계 램프 다음으로 큰 것. 없으면 "색을 두 단계로 칠한 플라스틱" 이다. **얼굴에는 안 넣는다** — 가장자리가 뜨면 눈매가 흐려진다 |
| **앞머리 그림자** | 얼굴 텍스처에 물결진 띠 | 없으면 이마가 무한히 넓다. 지오메트리 그림자로는 이 모양이 안 나온다 |
| **땋은 머리 고리** | 네 쌍 | "땋았다" 와 "손질했다" 의 차이. 중심 경로를 땋은 머리와 **공유**한다 |
| **치마 주름** | 각도별 반지름 물결 | 매끈한 원뿔은 천이 아니라 램프 갓이다 |
| **브로치·버클·부츠 덮개** | 작은 판 여섯 | 레퍼런스의 밀도는 형태가 아니라 **작은 것의 개수**에서 온다 |

그리고 이번 판에서 제일 큰 것 하나.

> **머리카락이 두피 위치를 짐작하고 있었다.**
>
> 앞머리 깊이를 사인 곡선으로 근사했더니 위쪽 절반이 두개골 속에 묻히고
> 끝만 이마 밖으로 삐죽 나왔다. `head.headFrontZ(y, x)` 를 만들어
> **머리에게 물어보게** 고쳤다 — 머리 지오메트리와 이 함수가 같은
> 조종점 표(`HEAD_KEYS`)를 본다. 이 저장소가 도시에서 스무 번 배운
> "같은 값을 두 곳에서 계산하지 말 것" 이 여기서도 똑같이 나왔다.

```
삼각형 44,228 -> 60,628 · 부품 106 -> 138 · 빌드 137ms (그대로)
```

### 4.6 3차 — "인체공학적으로" 와 "얼굴이 무섭다"

두 지적이 서로 다른 문제를 정확히 짚었다.

**얼굴이 무서웠던 진짜 이유는 눈이 아니라 눈썹이었다.**

```
안쪽 끝 +0.35h · 바깥 끝 +0.10h    <- 안쪽이 더 낮다 = 찌푸린 눈썹
안쪽 끝 +0.02h · 바깥 끝 +0.34h    <- 바깥이 내려간다 = 순한 눈썹
```

눈을 한 픽셀도 안 건드리고 인상이 바뀐다. 함께 고친 것 — 아래 눈꺼풀을
깊게 파서 눈을 둥글게 · 바깥 눈초리를 덜 치켜서 · 눈매 색을 순검정에서
보라빛 갈색으로 · 홍채 테두리 불투명도 0.9 -> 0.62 · **동공을 크게**
(유형성숙: 동공이 작으면 노려보는 눈이다) · 애교살 한 줄 · 아랫입술 그늘.

**인체는 로프트의 한계가 그대로 드러나 있었다.**

로프트는 수평 단면을 쌓는다. 그대로 두면 윗면이 평평해서 **어깨가 옷걸이**다.
사람 어깨는 목에서 팔로 내려간다. `deform` 이 y 를 바꿀 수 있다는 점을 써서
바깥으로 갈수록 링을 내렸다 (`shoulderFall`, 목 둘레 ±32mm 는 안 내린다 —
거기가 승모근이 솟은 자리다).

| | 전 | 후 |
|---|---|---|
| 어깨 | 평평한 윗면 | 목에서 팔로 62% 경사 |
| 목 | 균일한 관 | 아래가 승모근으로 벌어져 어깨에 앉는다 |
| 다리 | 위에서 아래로 균일한 원뿔(죽마) | 종아리 배 + 무릎이 앞으로 |
| 발 | 둥근 덩어리 | 앞으로 1.35배, 뒤꿈치는 그대로 |
| 삼각근 | 어깨 위에 얹힌 공 | 팔 뿌리 높이로 내려 붙음 |

그리고 **또 같은 결함이 나왔다.**

> 무릎을 앞으로 밀었더니 무릎만 스타킹을 뚫고 나왔다. 다리와 스타킹이
> **각자 자기 조종점 표**를 들고 있었기 때문이다. `surface.sampleKeys` 를
> 만들어 스타킹이 `LEG_KEYS` 를 받아 두께만 더하게 고쳤다.
>
> 도시에서 스무 번, 여기서 두 번째다 — 껍질은 속에 든 것과 같은 곡선이어야 한다.

땋은 머리도 바깥으로 넘겼다. 어깨 안쪽에 붙어 있어서 정면에서 팔이 통째로
가렸다 — 머리카락이 아니라 망토였다.

```
삼각형 60,628 -> 61,940 · 30뷰 전부 일치 · 경고 0
```

### 4.7 4차 — 3/4 에서 무너지는 이유는 두상에 뼈가 없어서다

정면만 보고 다듬었더니 조금만 돌리자 가면이 됐다. 원인 둘.

**하나. 두상이 눌러 놓은 계란이었다.** 사람 얼굴 앞면을 만드는 것은 뼈 다섯과
그 사이의 면이다 — 전두골 눈두덩(眉弓) · 안와 · 비골 능선 · 관골(광대) ·
하악(턱끝 융기와 하악각). 애니 두상은 이걸 다 죽이지만 **0 으로 만들지는
않는다.** 코가 정확히 0 이면 옆에서 얼굴이 벽이 되고, 그게 '사람이 아니다' 로
읽히는 첫 신호다. `faceStructure()` 로 다섯을 전부 얹었다 (코 17.5mm ·
눈두덩 4.2mm · 안와 −3.2mm · 광대 3.8mm · 턱끝 6.0mm). 아래턱 단면의
각짐(k)도 2.4 -> 2.9 로 올렸다 — 둥근 타원은 턱이 없는 얼굴이다.

**둘. 평행 투영은 z 를 안 본다.** 옆면과 뒤통수가 같은 u 를 받아 눈이 귀 뒤까지
늘어붙었다. 앞을 향한 면만 그림을 받고 옆으로 돌아가는 면은 u 를 텍스처
가장자리(민 살색)로 밀었다 — 실무 얼굴 언랩을 흉내내는 가장 싼 방법이다.

같이 고친 것 — 귀를 뿔에서 **납작한 판**으로 (귓불·귓바퀴·오목한 concha,
광대활 뒤 눈높이~코끝 높이) · 목을 앞으로 10도 (경추 전만; 수직이면 머리가
어깨 뒤에 얹혀 로봇이다) · **쇄골** 추가 · 앞머리 두께 13mm -> 7.5mm.

그리고 **세 번째로 같은 결함.**

> 뒷머리 다섯 가닥이 전부 두개골 **속**에 있었다. 좌표를 손으로 적었기
> 때문이다. `headFrontZ(y, x, back)` 로 뒤통수 표면도 물어보게 고쳤다.
> 앞머리에서 한 번 겪고도 뒷머리에 같은 실수를 했다 — **한 번 찾은 종류는
> 전수로 훑어야 한다**는 규칙을 또 어겼다.

```
삼각형 61,940 -> 63,300 · 30뷰 전부 일치 · 경고 0
```

### 4.8 5차 — 얼굴 한가운데가 광대보다 **뒤에** 있었다

사용자가 두 장을 그려 보냈다. 1번이 되어야 하는 얼굴, 2번이 지금 얼굴 —
**이마에서 턱까지 가운데가 골짜기로 파인** 얼굴.

맞았다. 그리고 원인은 코가 작아서가 아니라 **정면 평면성을 곱셈으로 구현한 것**
이었다.

```js
z *= 1 - 0.34 * (1 - |x| / 0.074) ** 2      // 틀렸다
```

이 식은 **중앙을 제일 세게 누른다.** 눈높이에서 실제로 재 보면

```
코 자리 0.0815   광대 0.0926      <- 얼굴 한가운데가 광대보다 11mm 뒤
```

계곡을 파 놓고 그 위에 코를 17mm 얹었으니, 코가 있는 게 아니라 골짜기에
둔덕이 하나 있었던 것이다. 앞선 네 판에서 코를 키우고 뼈를 얹은 것이
효과가 없었던 이유다 — **바닥이 내려앉아 있었다.**

올바른 뜻은 "눌러서 얕게" 가 아니라 **"단면을 각지게"** 다. 초타원의 지수를
올리면 두께는 유지한 채 중앙이 평평해지고 광대에서 꺾여 옆면으로 넘어간다.

```
k = 2.4 (두상)     중앙 1.000 · 광대 0.906 · 관자 0.766   부드러운 타원
k = 5.5 (앞면)     중앙 1.000 · 광대 0.994 · 관자 0.961   판판한 앞면
```

고친 뒤 실측 (센터 -> 바깥, 단위 m):

| 높이 | x=0 | 0.030 | 0.055 | 0.075 |
|---|---|---|---|---|
| 눈썹 1.487 | **0.1005** | 0.0954 | 0.0912 | 0.0850 |
| 눈 1.455 | **0.1010** | 0.0867 (눈확) | 0.0904 | 0.0847 |
| 코끝 1.416 | **0.0947** | 0.0781 | 0.0762 | 0.0507 |

모든 높이에서 가운데가 제일 앞이다.

> **교훈: 형태를 비율로 곱하지 말 것.** 곱셈은 큰 값을 많이 줄인다 —
> 중앙이 제일 크므로 중앙이 제일 많이 사라진다. 형태를 바꾸고 싶으면
> **목표 형태를 직접 쓰고 거기로 섞어야** 한다.

### 4.9 연동 시험 — 남의 리그 위에 코드 생성물을 얹을 수 있나

genex SKATE 를 열어 뭘 받아 가는지 직접 봤다. `meshy-girl4.json` 의
`provenance` 에 경로가 그대로 적혀 있다.

```
nano-banana-pro (컨셉 이미지) -> meshy-6 (34만 면 생성) -> 1만 면 리메시
  -> 자동 리깅(meshy-biped) -> rigged-character.glb + core27 모캡
```

**사람은 코드가 아니다.** 전용 생성기가 만든 애셋이고 코드는 그걸 움직인다.
그러면 남는 질문은 하나 — 그 경로에서 코드 몫이 실제로 존재하는가.

남의 애셋은 안 가져왔다. 이 저장소가 이미 내보낸 `export/character.glb`
(본 17개)를 **외부 애셋인 셈 치고** 다시 불러들여 쟀다 (`rigtest.js`,
`window.__rig()`).

```
불러오기 5ms · 본 17 · 스킨드 6 · 클립 4 · 머리뼈 "Head" 발견
축척 1.104 자동 (상대 머리 높이에서 유도)
코드 생성물 20개 부착 · 삼각형 228 -> 20,692
머리뼈 0.6rad 회전 시 머리카락 정점 이동 0.0771m  <- 따라온다
재출력 GLB: JOINTS_0/WEIGHTS_0 보존 · extensionsRequired 없음 · 블렌더 차단 없음
```

**배관이 뚫려 있다.** 생성기 GLB -> 코드로 얹기 -> GLB 재출력 -> 블렌더 -> 유니티.

### 4.10 머리카락 본 체인과 스프링

강체 부착은 고개를 돌릴 때 1.4m 짜리 땋은 머리가 통째로 휙 돈다.
가닥마다 본 15개를 심고 스프링을 걸었다 (`spring.js`).

스키닝은 **UV 로 한다.** `sweep()` 의 v 가 이미 경로 위치(0 뿌리 ~ 1 끝)라
정점이 사슬 어디쯤인지가 적혀 있다. 좌표로 다시 찾으면 같은 값을 두 곳에서
계산하는 셈이고 굵기를 바꾸는 순간 어긋난다.

**파라미터는 손으로 짐작해서 두 번 틀렸다.** 그래서 쓸었다.

| 강성 | 감쇠 | 정지 처짐 | 최대 이탈 | 최종 |
|---|---|---|---|---|
| 3 | 0.50 | 31mm | 506mm | 126mm |
| 3 | 0.85 | 31mm | **653mm** | 126mm |
| 6 | 0.70 | 16mm | 343mm | 118mm |
| **12** | **0.70** | **8mm** | **145mm** | 114mm |
| 24 | 0.70 | 4mm | 117mm | 113mm |

`최종 114mm` 가 강체였을 때의 이동량이다. 강성 12 에서 그보다 31mm 만
더 흘렀다가 돌아온다 — 눈에 보이는 지연이면서 발산하지 않는다.
24 는 지연이 사라져 강체와 구분이 안 된다.

> **감쇠는 복원이 충분할 때만 도움이 된다.** 무른 사슬에서 감쇠를 올렸더니
> 돌아오는 속도까지 죽어 **더 멀리** 흘러갔다 (506 -> 653mm).
> 직관과 반대라 쓸지 않았으면 못 찾았다.

그리고 또 같은 결함 — **땋은 머리 고리가 제자리에 남았다.** 정적 지오메트리로
뒀기 때문이다. 이제 해당 t 의 본에 매단다. "따라가야 하는 것이 안 따라간다" 가
이 캐릭터에서만 네 번째다.

**남은 것: 충돌체가 없다.** 크게 흔들리면 땋은 머리가 몸을 스친다.
VRM 은 구체 콜라이더를 쓴다 — 몸통에 캡슐 두엇이면 된다.

### 4.11 레퍼런스와의 거리

닿은 것 — 실루엣(은발 트윈 땋은 머리·뿔·비대칭 스타킹) · 얼굴 인상 ·
툰 셰이딩과 선 · 6.5등신 비율.

**안 닿은 것** — 손가락(지금은 주걱) · 의상 디테일(레퍼런스는 장식이 수십 개) ·
표정(블렌드셰이프 없음) · 리그 · 머리카락 물리 · 옷 주름 · 재질의 결.
그리고 **디자인 자체는 다른 사람의 것**이라 "비슷한 부류" 까지가 한계다.

2차 뒤에도 **여전히 절반 언저리다.** 손가락과 장식이 붙어 "미완성" 딱지는
뗐지만, 못 간 절반은 그대로다 — 표정(블렌드셰이프) · 리그 · 머리카락 물리 ·
옷 주름의 결 · 그리고 얼굴 조형 자체. 강의 39강 중 25강인 부분이다.

**남은 것 중 코드로 갈 수 있는 것**: 리본·프릴·레이스 같은 규칙 있는 장식,
의상 레이어 추가, 부츠·장갑 디테일, 포즈. **코드로 못 가는 것**: 얼굴 조형의
마무리, 텍스처의 결, 표정.
