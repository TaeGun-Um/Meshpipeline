# 씬 3 — 모델 테스트 (동결)

```
web/?scene=model-test
```

높은 수준의 3D 모델링이 코드로 어디까지 되나를 시험한 자리. 나무 상자(재질
검증용)와 서브컬처 아바타 — 툰 셰이딩 · 땋은 머리 스프링 · 얼굴 텍스처 — 가
있다. **이 씬은 동결이다** — 작업 계획이 없고, 다시 열지 않는다. 씬은 빌드
가능한 상태로 보존한다.

## 동결 시점의 실측

```
삼각형 61,380 · 텍스처 9MB · 검증 뷰 4개 (mt_face · mt_front · mt_three · mt_crate)
캐릭터: 6.5등신 · 본 체인 땋은 머리 x2 (본 15개씩) · 스프링 물리 · 툰 3단 램프
```

## 이 씬에서 남은 것 — 지식의 위치

**결론과 규칙 전부가 [character.md](character.md) 에 있다.** 캐릭터·유기형을
다시 만들 일이 생기면 그 문서부터 — 도구 선택 기준, 치수의 단일 출처, 형태의
규칙(비율 곱 금지·애니 얼굴의 뼈·두피를 물어보는 머리카락), 그림과 셰이딩의
규칙, 반복된 결함 대장, 그리고 **코드로 갈 수 있는 것과 못 가는 것의 경계**까지.

씬을 안 가리는 교훈 — "계측이 강할수록 계측 밖을 놓친다"(3.8), "껍질은 속에
든 것과 같은 곡선을 봐야 한다"(3.9), 형태·선·감쇠의 규칙(3.1x 일부) — 는
[../../lessons.md](../../lessons.md) 로 갔다.

## 결론 요약

절차적 코드는 **규칙이 지배하는 형태**(땋은 머리·의상 규칙 장식)에는 강하고,
**취향이 지배하는 형태**(얼굴 조형·텍스처의 결·표정)에는 약하다. 후자가
필요하면 외부 생성 파이프라인(`tools/meshy.mjs` — 유료 플랜 필요)에 베이스
메시를 맡기고 코드 생성물을 리그에 얹는 하이브리드가 검증된 경로다
(리깅 GLB → 본에 부착 → 재익스포트까지 왕복 확인 완료).
