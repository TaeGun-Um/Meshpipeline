# 인수인계

다음 세션에서 이 프로젝트를 이어받을 때 **가장 먼저 읽을 문서**다.

---

## 1. 5분 안에 파악하기

```bash
node web/server.mjs
# http://localhost:5173/?scene=night-city
```

```js
__audit()          // 예산·규약·개수·**배치** 점검
__place()          // 배치 검사 전문 — 관통·부유가 어디서 났는지
__stats.counts     // 간판·건물·사람·가로시설·골목 개수
await __lock()     // 현재 상태를 shots/ 에 렌더
```

**`__audit()` 경고 0건이 정상이다.** 배치 검사가 들어오면서 결함 일곱이
드러났고 전부 고쳤다 (`status.md` 0장). 경고가 뜨면 뭔가 깨진 것이니
**검사를 무르지 말고 배치를 고칠 것.**

```bash
node tools/verify.mjs        # 기준선과 픽셀 비교
```

**작업 시작 전에 `verify` 가 "전부 일치" 인지 확인한다.** 아니면 누가 뭘
바꿔 놓고 기준선을 안 잡은 것이고, 그 상태로 작업하면 원인 추적이 불가능해진다.

## 3. 이 프로젝트에서 반복된 실패 — 열두 번

원인이 크게 둘이다. 다음 사람이 열세 번째를 내지 않도록 적는다.

| # | 무엇 | 원인 |
|---|---|---|
| 1 | 자판기가 골목 입구를 막음 | 배치 모듈이 서로를 모름 |
| 2 | 골목 창이 공중에 뜸 | 벽 높이와 창 높이가 다른 상수 |
| 3 | 크레인이 도로 위에 섬 | 부두 폭이 크레인+야드보다 좁음 |
| 4 | 골목 벽이 공장 위로 치솟음 | 벽 높이 고정, 구역 건물 높이를 안 봄 |
| 5 | 브릿지가 허공에서 시작해 허공에서 끝남 | 건물 위치·높이를 모르고 배치 |
| 6 | **간판이 1,602 -> 9개로 죽음** | 인도 폭을 두 곳에서 다른 출처로 계산 |
| 7 | 홀로그램이 인도를 관통 | 인도 폭보다 멀리 띄움 |
| 8 | 슬럼 골조가 옆 건물을 관통 | 회전 후 크기를 계산해 놓고 **안 씀** |
| 9 | **주차 1,137대가 인도·건물 안에 섬** | `PITCH` 를 구간별로 갈면서 거기서 파생된 `BLOCK_SIZE`·`STREET_WIDTH` 를 안 고침 |
| 10 | 건물 수를 두 배로 신고 | 필지 루프와 구역별 생성기 다섯에서 **각각** 셈 |
| 11 | 랜드마크가 예약 블록이 아닌 딴 곳에 섬 | 격자가 6x6 이던 시절의 좌표식이 남음 |
| 12 | 횡단보도가 인도 판 밑에 깔림 | 연석 **바깥**에 그렸는데 인도 판이 16cm 위에 있다 |
| 13 | **고가도로가 건물 19동을 관통** | `HIGHWAY_X = -PITCH/2` 가 구간별 격자 이후 도로가 아니라 블록 판 안쪽이 됨 |

13번이 특히 중요하다. 배치 검사가 이걸 **못 잡았다** — `highway.js` 가
`b.mark()` 를 안 걸어서 원장에 아예 없었기 때문이다. 검사에도 사각지대가
있다는 뜻이다. **지오메트리를 만드는 모듈은 전부 표시를 걸어야 한다.**

9·11·12 는 전부 하나에서 나왔다 — **구간별 격자를 넣을 때 거기서 파생된
값을 같이 안 고쳤다.** 셋 다 해결했고, 다시 안 나게 유도값을 상수가 아니라
함수로 바꿨다 (`layout.roads()` · `blockCenter` · `blockIndexAt`).

9번은 여덟 번을 다 겪고 규칙까지 써 놓은 **뒤에** 난 것이다. 그리고 아무
검사에도 안 걸렸다. 배치 검사기를 만들고서야 나왔다 (아래 4장).

### 규칙 C — 상수를 바꾸면 거기서 유도된 것을 전부 따라간다

`PITCH = BLOCK_SIZE + STREET_WIDTH` 였다. `PITCH` 를 구간별로 가르면서
나머지 둘을 고정으로 뒀더니 셋의 관계가 깨졌고, 그 관계를 믿던 여섯 모듈이
전부 틀린 자리에 물건을 놓았다.

**유도값은 상수로 두지 말고 함수로 만든다.** 그래야 원본이 바뀔 때 따라온다.
지금 그렇게 바꾼 것 — `roads()` `blockCenter()` `blockIndexAt()` `blockPitch()`.

### 두 가지 규칙

**규칙 A — 놓기 전에 그 자리에 무엇이 있는지 묻는다.**

- 지면: `siteplan.js` 의 `claim(x, z, r, TIER, label)`
- 공중: `towers.anchors` (건물 사각형 + 옥상 높이 + 길에 면한 면)

새 배치 모듈이 이 둘을 안 거치면 **그게 결함이다.** 실제로 `port.js` 가
안 거쳐서 3번이 났다.

**규칙 B — 같은 값을 두 곳에서 계산하지 않는다.**

`status.md` 2.1 의 결합 대장을 볼 것. 특히:

1. 구역별 값이 있는 상수는 **반드시 구역(`districtAt`)에서 받는다.**
   전역은 폴백일 뿐이다 — `sidewalk` `grain` `alleyRate` `lamp` `skin`
   `furniture` `retrofit` `signDensity`
2. 두 모듈이 같은 숫자를 알아야 하면 `layout.js` 에 올린다.
   주석으로 "같아야 한다" 고 쓰지 않는다
3. 경계 조건을 등호로 만들지 않는다 (6번 버그가 정확히 등호였다)

## 4. 검증이 잡는 것과 못 잡는 것

| 도구 | 잡는 것 | 못 잡는 것 |
|---|---|---|
| `verify.mjs` | 화면이 달라졌다 | **무엇이** 사라졌는지 |
| `__audit()` 예산 | 너무 많다 | 배치가 틀렸다 |
| `__audit()` 하한 | 통째로 사라졌다 | 하나씩 어긋난 것 |
| **`__audit()` 배치** | **허공에 뜬 것 · 관통 · 차도 침범** | 보기 흉한 것 (그건 눈으로) |

마지막 줄이 이번에 들어왔다. 인수인계서가 "다음에 만들면 좋은 것" 으로
남겼던 그것이다 (`core/placement.js` · `scenes/night-city/placecheck.js`).
**들어오자마자 결함 일곱을 찾았고, 전부 앞의 세 검사를 통과하던 것들이다**
(`status.md` 0장). 일곱 다 고쳤다.

그중 셋(격자 불일치 · 랜드마크 좌표 · 횡단보도)은 **눈으로는 몇 세션 동안
못 봤던 것**이다. 주차 1,137대가 건물 안에 서 있는 것을 스크린샷 16장으로
못 잡았다는 사실이 이 검사의 존재 이유다.

### 배치 검사가 어떻게 만들어졌나 — 다음에 검사를 만들 때 쓸 것

세 가지가 요점이다. 셋 다 실제로 검사를 두 번 틀리고서 얻었다.

**1. 신고를 믿지 말고 그려진 것을 읽는다.**
모듈이 "여기 이만한 것을 놓았다" 고 신고하게 만드는 쪽이 훨씬 쉽다. 그런데
8번 버그가 정확히 **계산해 놓고 안 쓴** 것이었다 — 신고를 믿는 검사였으면
검사도 같이 속았다. `MeshBuilder.mark(kind, label)` 으로 구간을 열면 그
뒤의 조각 경계가 하나로 합쳐진다. 인스턴스 메시는 행렬에서 직접 읽는다.

**2. 상수를 믿지 말고 실물을 잰다.**
처음에는 도로를 `STREET_WIDTH/2` 로 정의했다. 그러면 **그 상수가 틀렸을 때
같이 속는다** — 그리고 실제로 틀려 있었다 (9번). 지금은 도로를 블록 판
사이의 빈 공간으로 정의한다. 그래서 9번이 잡혔다.

**3. 상자 하나로는 "넓은 부분이 높이 있다" 를 표현 못 한다.**
디지털 수목의 우듬지가 차도 위로 뻗는 것을 "5m 침범" 으로 보고했다. 머리
위로 지나가는 것은 결함이 아니다. 그래서 **4.5m 아래 조각만의 평면 범위**를
따로 잰다 (`placement.lowBox`). 데크 상판은 안 걸리고 그 기둥은 걸린다 —
그게 알고 싶은 것이다.

그리고 **관측만 한다.** 도입 전후 16뷰가 픽셀 단위로 동일하다. 작업 중인
씬에 안전하게 넣을 수 있다는 뜻이다.

**새 시스템을 추가할 때는 `audit.js` 의 `EXPECT` 에 하한을 함께 추가한다.**
그리고 씬이 `counts` 로 신고해야 감사가 볼 수 있다
(`index.js` -> `Scene.build` -> `__stats.counts`).
**지면·공중에 물건을 놓는 모듈이면 `b.mark()` 도 함께 건다.**

### 6.0 (완료) 격자 불일치 — 도로를 피치에 맞췄다

`BLOCK_SIZE`(66) + `STREET_WIDTH`(22) = 88 인데 구간 피치는 74·88·104·82 다.
**12구간 중 3개에서만 맞는다.** 피치 74 구간은 실제 도로가 8m 뿐이라
블록 판이 도로를 양쪽에서 7m 씩 먹고, 그 결과 갓길 주차 1,137대(57%)가
인도와 건물 안에 서 있다. 자세한 것은 `status.md` 0.1.

**(나) 로 고쳤다** — 블록은 66m 로 두고 도로가 남은 공간을 갖는다.
`city.md` 1기의 "마차가 다니던 시절이라 촘촘하다" 와 맞고, 골목이 아닌
**좁은 길**이 도시에 생긴다.

`STREET_WIDTH` 는 이제 `layout.js` 밖으로 안 나간다. 도로가 필요하면
`roads()` 를 부른다 — `{ lo, hi, mid, width }` 를 준다.

**연석에서부터 재라.** 구간 경계에서는 도로가 격자선 기준으로 비대칭이라
"격자선에서 ±얼마" 는 반드시 한쪽이 틀린다.

### 6.1 "도로 건물 직각" — 절반

| | 상태 |
|---|---|
| 구간별 다른 피치 (1기 매립 차수) | **완료** — 74·88·104·82m, 도로 폭 8~38m |
| 슬럼이 비스듬히 앉음 | **완료** — 15~35도 |
| 옛 간선 (0기) | **만들었다가 폐기** |
| 고가 사선 (3.5기) | **폐기** |

옛 간선은 실제로 구현했다가 걷어냈다. 이유는 `city.md` 의 '사선 둘을 폐기한
이유' 에 적었다 — 요약하면 **필지가 축 정렬 사각형인 채로 사선만 그으면
격자가 안 깨지고 갉아먹은 자국만 남는다.**

그래서 남은 방향은 사선이 아니라 **대지 단위를 바꾸는 것**이다 (6.2 · #25).

### 6.2 보행 전용 구역

차도 하나를 통째로 없애고 블록 두셋을 붙여 그 안을 좁은 통로만으로 채우는
것. 3기(포화)의 산물 — 사람이 넘쳐 도로를 점유했고 차가 못 들어가게 됐다.

지금 골목은 블록 **안**에 파는 것이라 여전히 사방이 도로다. 이건 도로 자체를
지우는 작업이고, `streets` `sidewalk` `parking` `crowd` 가 "여기엔 도로가
없다" 를 알아야 한다.

### 6.3 슬럼 내부 다양화

지금 슬럼 블록은 전부 미완성 골조 하나뿐이라 반복적이다. 셋을 섞어야 한다.

| | 비중 | 무엇 |
|---|---|---|
| 미완성 골조 | 35% | 지금 것. 소수여야 눈에 띈다 |
| 무단 증축 저층 | 45% | 낡은 건물 위에 제멋대로 덧대 올린 것 |
| 빈 터 · 잔해 | 20% | 철거하다 만 자리 |

### 6.4 구역별 랜드마크

손 배치. **절차적으로는 안 나온다** — 통계에서 빼내야 특별해진다.
`landmark.js` 가 이미 그 방식인데 지금 도심에만 쓰인다.

사용자가 예로 든 것: 사이버펑크 2077 요시노부 퀘스트의 기업 퍼레이드
광장 같은 곳 — "저기서 무슨 일이 일어났다" 가 성립하는 장소.

### 6.5 지형 고저차

`surfaceHeight()` 가 상수를 돌려준다. 물가 단면(호안 비탈·안벽)만 만들었고
도시 내부는 완전한 평면이다.

**방법은 정해졌다**: `MeshBuilder.add()` 에서 조각의 **무게중심 높이만큼**
Y 를 옮긴다 (`bakeTextureRepeat` 이 `Scene.build()` 공통 패스인 것과 같은 방식).
조각 단위로 옮기면 건물이 안 기울고 모든 모듈이 자동으로 따라온다.

**걸리는 것은 노면 하나뿐** — 지금 평면 한 장이라 통째로 움직이므로
`streets.js` 에서 격자로 잘게 나눠야 한다.

곶이므로 중심이 높고 물가로 내려가는 것이 자연스럽다.

### 6.6 건물 출입구 — 미착수

지금 점포는 **벽감뿐이고 문이 없다.** 넷이 필요하다.

| 종류 | 어디에 | 구성 |
|---|---|---|
| 상점 출입구 | 점포 벽감 안 | 유리문 + 손잡이 + 위 조명 + 앞 단 |
| 로비 출입구 | 기업·주거 포디움 | 큰 캐노피 + 회전문 + 밝은 실내 (corpo 는 있음) |
| 서비스 출입구 | 골목 | 철문 (**있음** — alley.js) |
| 차량 진입로 | 포디움 측면 | 롤셔터 + 경사로 + 노란 경계선 |

**배치 계획 연동이 빠졌다.** 출입구 앞은 `TIER.ACCESS` 로 확보해야 하는데
지금은 골목 입구만 등록돼 있다. 그래서 **자판기가 가게 문 앞을 막을 수 있다.**

### 6.9 남은 결함

- ~~**구역이 듬성듬성하다**~~ — **해결.** 4x4 덩어리마다 해시를 굴리던 것을
  **씨앗 + 가중 보로노이**로 바꿨다 (`district.SEEDS`). 덩어리 수 14 -> 11 도
  줄었지만 더 큰 변화는 **경계 모양**이다 — 옛 방식은 구역 경계가 반드시
  4블록 격자 위에 놓여서 지도에 정사각 얼룩으로 보였다. 씨앗은 그런 축이 없다.
- ~~**공업 구역과 항만이 어긋난다**~~ — **해결.** 공업 씨앗을 물가(-X 항만과
  ±Z 물가)에만 두고 육지 쪽(+X)에는 두지 않는다. 전에는 항구 없는 자리에
  공장이 났다.
- **맨홀·물웅덩이가 배치 계획 밖이다.** 차도에만 있어 인도 물건과 안 겹치므로
  우선순위를 낮게 봤는데, 갓길 주차가 들어온 뒤로는 겹칠 수 있다
- **공업 구역과 항만이 어긋난다.** 공업은 `core > 0.62` 로 **사방 외곽**에
  나는데 항만은 -X 한 변에만 있다. 육지 쪽 공업 구역은 항구가 없는데 공장이
  있는 셈이다. 공업을 물 쪽으로 치우치게 하거나, 육지 쪽은 다른 성격
  (폐기물 처리·발전소)으로 나눠야 맞다
- **구역이 아직 듬성듬성하다.** 뭉치는 단위를 3x3 -> 4x4 로 키웠지만
  `districtAt` 이 여전히 **덩어리마다 해시를 새로 굴리므로** 인접 덩어리가
  같은 구역이 될 보장이 없다. 진짜로 몰아주려면 시드 몇 개를 심고 거기서
  자라게 하는 방식(보로노이·플러드필)이 필요하다
- **데크·계단이 실제로 올라가지는지 미검증.** 건물 정면에 붙였지만
  적층 상가의 층별 외부 복도와 이어지는지는 확인하지 않았다

### 6.10 간판 종류 — 한 가지뿐

지금은 **사각 발광판 + 픽셀 글자**, 색만 다르다. 개수(866)가 아니라
종류가 문제다.

- **구부린 튜브 네온** — 진짜 네온의 특징인 윤곽선 형태. 채워진 판이 아니다
- **간판 위 3D 조형물** — 거대한 라면 그릇·병·동물. 카부키를 기억하게 만드는 것
- **깨지고 꺼진 간판** — 전부 멀쩡히 켜져 있는 게 오히려 비현실적이다
- **영상 광고판** — 큰 화면에 이미지

### 6.11 소품 조형

마네킹(원통+구), 선반 상품(작은 상자), 차양(평판). `metalCrate` 텍스처로
쓰레기통·상자·컨테이너는 고쳤지만 나머지는 형태가 거칠다.

## 7. 씬 구조

```
core/          엔진. 씬을 하나도 모른다
  scene.js       Scene 기반 클래스. build() 가 공통 패스를 건다
  audit.js       예산·규약·개수 점검
  placement.js   배치 기록과 판정. 그려진 지오메트리에서 경계를 읽는다
  builder.js     MeshBuilder. mark() 로 배치 기록 구간을 연다
  siteplan.js 는 씬 안에 있다 (night-city 전용)

  siteplan 과 placement 는 짝이다 — **놓기 전에 묻는 쪽**(claim)과
  **놓은 뒤에 재는 쪽**(mark). 앞은 겹침을 막고 뒤는 못 막은 것을 잡는다.

scenes/night-city/
  layout.js      격자·구역 없는 순수 좌표. **공유 상수는 전부 여기**
  district.js    구역 표와 배치 규칙
  siteplan.js    지상 배치 계획 (6등급 우선순위)
  towers.js      건물 오케스트레이션 + 앵커 생산
  bazaar/housing/factory/corpo/slum.js   구역별 생성기 다섯
  alley/vertical/holo/crowd/parking/port/sidewalk/...
```

**빌드 순서 = 배치 우선순위**다 (`index.js`).

```
골목 입구 -> 건물 -> 수직 동선 -> 조명·노면 -> 편의 시설 -> 인파
```

건물이 수직 동선보다 먼저여야 데크·브릿지가 어디 붙을지 알 수 있고,
수직 동선이 조명보다 먼저여야 가로등이 계단 착지점을 피한다.
**이 순서를 바꾸면 배치가 깨진다.**
