# 기능 모듈

## 1. 브라우저 — 코드로 3D를 만든다

### 원리

3D 물체는 결국 숫자 목록이다. 정점 좌표와 텍스처 픽셀을 **수식으로 계산**한다.
저장소에 이미지·모델 파일이 하나도 없는 이유다.

```js
// web/src/scenes/vacant-lot/scatter.js — 잎 하나
const w = halfW * (1 - Math.pow(t, 1.35) * 0.93);  // 끝으로 갈수록 좁아진다
const z = 0.17 * t * t;                             // 끝으로 갈수록 휜다
```

정점 12개, 공식 두 줄. "풀잎을 그린" 게 아니라 "풀잎이 되는 수식"을 쓴 것이다.

### `core/rng.js` — 시드 고정 난수

`mulberry32`. **`Math.random()` 을 쓰지 않는다.** 같은 시드면 언제 어디서 열어도
동일한 씬이 나와야 하고, 그래야 스크린샷 비교로 품질을 판정할 수 있다.
시드는 `20260730`.

### `core/noise.js` — 값 노이즈와 fbm

격자에 난수를 뿌리고 사이를 부드럽게 보간한 뒤, 주파수 2배·진폭 절반으로 여러 겹 쌓는다.

타일링이 핵심 난관이었다. 노이즈 격자를 `cells` 로 wrap하고 샘플 좌표 범위를 항상
`cells` 의 정수배로 맞춘다. 그러면 오른쪽 끝 값 = 왼쪽 끝 값이 되고, 옥타브가 주파수를
2배씩 올려도 정수배가 유지되므로 모든 층에서 이음선이 사라진다.

### `core/textures.js` — 픽셀 루프로 텍스처를 굽는다

`f(u, v) → 색` 함수를 512×512 픽셀에 대해 호출한다. 한 번의 루프에서 **색·거칠기·노말**
3장을 동시에 뽑는다. 공터는 픽셀 루프로 73장을 굽고 약 0.5초,
도시는 285장에 약 25초가 걸린다 — **빌드 시간을 지배하는 것이 이것이다.**

재료는 두 가지뿐이다.

- **노이즈** (자연물): 흙·아스팔트·녹·도장 벽면. 흙은 fbm을 주파수 4/2/64/32로 네 겹.
- **나머지 연산** (인공물): 벽돌·시멘트 블록. `ri % 2 ? 0.5 : 0` 이 벽돌 쌓기 패턴이고,
  블록별 색 편차는 정수 해시(`hash2`)로 낸다 — 노이즈로는 불연속 값이 안 나온다.

**색보다 거칠기·노말이 중요하다.** 담장은 기하학적으로 납작한 박스 6면인데 블록이
튀어나오고 줄눈이 파여 보인다. 노말맵이 빛 받는 각도를 속이기 때문이다.

> **노말맵 강도 함정**: `NORMAL_STRENGTH` 를 3.2로 두면 자갈처럼 픽셀 단위로 높이가
> 튀는 텍스처에서 노말이 거의 수평으로 눕고, 대부분의 픽셀이 광원 반대를 향해
> **표면이 새카맣게 죽는다.** 브라우저는 ACES 톤매핑이 이를 가려주지만 톤매핑이 없는
> 엔진에서는 그대로 드러난다. 현재 1.4.

### `core/meshkit.js` — 정적·동적 공통 지오메트리

`mergeParts` 는 여러 조각을 하나의 `BufferGeometry` 로 합치고, 머티리얼별로 그룹
(서브메시)을 만든다. `extras` 로 정점당 추가 속성을 주입할 수 있어서 인스턴싱과 스키닝이
같은 병합 코드를 공유한다.

`bakeInstances` / `bakeInstancedDescendants` 는 `InstancedMesh` 를 실제 정점으로 굽고
`instanceColor` 를 `COLOR_0` 으로 옮긴다. 익스포트 시점에만 임시로 교체하고 `finally` 로
되돌리므로 씬은 계속 인스턴싱으로 돌아간다.

`metricBox(w,h,d,at,tile)` 는 텍스처가 **미터 단위로** 반복되는 박스를 만든다.
`BoxGeometry` 의 UV는 면마다 0..1 이라 13m 벽에도 텍스처가 딱 한 장 늘어나서 콘크리트가
벽지처럼 보인다. `scaleUV` 는 같은 일을 임의 지오메트리에 한다.

> **왜 `texture.repeat` 이 아니라 UV인가**: `repeat` 은 glTF 로 나갈 때
> `KHR_texture_transform` 확장이 되고, 반복 수가 다른 조각마다 머티리얼을 복제해야 한다.
> UV에 구우면 조각이 몇 개든 머티리얼 하나를 공유하고 확장도 필요 없다 — UV는
> 지오메트리라 어느 포맷에서도 그대로 간다. 나이트시티에서 창문 머티리얼이 건물
> 20개당 20개에서 시트당 1개(총 4개)로 줄었다.

`Scene.build()` 는 마지막에 `meshkit.bakeTextureRepeat()` 을 모든 씬에 건다.
`texture.repeat` 을 UV 에 구워 glTF 에 `KHR_texture_transform` 이 붙을 여지를
없앤다 — 셰이더가 하는 계산과 동일하므로 화면은 바뀌지 않는다.
자세한 사정은 [verification.md](verification.md) 참고.

### `core/boxfaces.js` — 직각 건축 좌표 계산

건물·방·구조물은 대개 축에 정렬된 사각형 `{x0,x1,z0,z1}` 이고, 거기 붙는 것들(창문 피부,
간판, 셔터, 처마)은 전부 "어느 면의, 어디에, 얼마 크기로" 다. `facePlane` · `outward` ·
`faceAnchor` · `bayRect` · `shrink` · `rectBox` 가 그 계산을 맡는다.

> **왜 뽑았나**: 부호를 틀린다. 점포를 건물 안쪽으로 파려면 `inner + sign*depth` 인데
> `-` 로 써서 점포가 골목 한가운데로 튀어나온 적이 있다. `outward()` 주석에 그 규약이
> 한 곳에만 적혀 있다.

### `core/material.js` — 마스터 머티리얼

언리얼의 마스터/머티리얼 인스턴스와 같은 구조. 자세한 설계 이유는
[architecture.md](architecture.md#부모-클래스-셋) 참고.

```js
const Neon = Glow.derive('Neon', { intensity: 1, tint: 0.06 });  // 파생 = 상속
const a = Neon.instance({ color: 0x2ff2ff });
const b = Neon.instance({ color: 0x2ff2ff });
a === b   // true — 값이 같으면 같은 객체
```

`materialReport()` 로 생성·공유 횟수를 볼 수 있다. 나이트시티: 발광 재질 요청 956건 →
머티리얼 6개.

> **색공간 함정**: `new THREE.Color(0xrrggbb)` 는 sRGB로 해석해 선형으로 변환하지만,
> `new THREE.Color(r/255, g/255, b/255)` 는 **변환하지 않는다**. 팔레트 숫자를 텍스처에서는
> sRGB 캔버스 값으로 쓰면서 단색 머티리얼에서는 선형으로 넘겨서, 같은 팔레트 값인데
> 단색 부품만 텍스처보다 4배 이상 밝았다. 지금은 마스터가 항상 16진(sRGB)으로 받는다.

### `core/builder.js` — MeshBuilder

`조각 수집 → 병합 → Mesh → 플래그 → Group → scene.add` 를 8개 모듈이 반복하던 것을
흡수한다. `attributes` 로 정점 속성을 추가할 수 있다 (빛 웅덩이가 색을 정점에 실어
드로우콜을 하나로 유지하는 데 쓴다).

> **기본값 주의**: 맨 `new THREE.Mesh` 는 `castShadow`/`receiveShadow` 가 둘 다 꺼져 있고
> `MeshBuilder` 는 둘 다 켜져 있다. 옮길 때 확인하지 않으면 그림자 동작이 조용히 바뀐다 —
> 실제로 차선 페인트가 달 그림자를 받아 노면보다 1/3 어두워졌다.

### `core/scene.js` — Scene 부모 클래스

`meta` 기본값·검증, 환경맵 굽기, `build()` 오케스트레이션. 서브클래스는
`surfaceHeight()` 와 `createWorld()` 만 구현한다.

`bakeEnvironment(scene, renderer, {source})` 의 `source` 가 중요하다.

| source | 언제 | 왜 |
|---|---|---|
| `'sky'` | 낮 씬 | 태양이 이미 모든 것을 밝히고 있다. 하늘돔만 구우면 충분하다 |
| `'scene'` | 야간 씬 | **발광 표면은 주변을 밝히지 않는다.** 하늘만 구우면 네온 도시가 통째로 검게 나온다 |

## 1.5 공유 레시피 (`shared/`)

둘 이상의 씬이 쓰는 것들. 판단 기준은 "지금 실제로 둘 이상이 쓰는가" 다.

| 모듈 | 무엇 |
|---|---|
| `neon.js` | 네온 색, 간판 배색 조합, 야간 표면 알베도 기본값 |
| `urban/surfaces.js` | 젖은 아스팔트·인도·콘크리트 패널·타일 외벽·셔터 |
| `urban/facades.js` | 창문 시트·유리 커튼월·펀칭 콘크리트 (건물 한 면을 덮는 큰 시트) |
| `urban/shops.js` | 점포 실내 배경·점포 정면 |
| `glyphs.js` | 폰트 없는 표의문자 간판 (배너·세로 간판·광고판) |
| `lightpool.js` | 가산합성 빛 웅덩이 |
| `movers.js` | 직선 항로 왕복 운동 (지상·공중 교통 공유) |
| `sky.js` | 그라디언트 하늘돔 |
| `masters.js` | 파생 마스터 (NeonTube · SoftGlow · Beacon · LightPool · Headlight) |

`urban/` 은 **팩토리**다. 레시피는 공유되지만 알베도 팔레트는 씬이 정한다.
셋으로 나뉘어 있지만 `urbanTextures()` 가 합쳐서 하나의 객체로 돌려주므로
쓰는 쪽 코드는 나뉘기 전과 같다.

```js
const T = urbanTextures(MY_SURFACE);
const asphalt = T.wetAsphalt();
```

나눈 기준은 성격이다. `surfaces` 는 넓은 면을 타일링으로 덮으므로 이음매가
없어야 하고, `facades` 는 한 장이 건물 한 면을 덮으며 창문 격자와 발광을
담고, `shops` 는 눈높이에서 읽히므로 상품·선반 같은 '내용' 이 있어야 한다.
한 파일 719줄이었을 때는 아스팔트를 고치러 들어갔다가 커튼월 코드를 스크롤로
지나가는 일이 반복됐다.

### 표의문자 간판을 폰트 없이

한자·가나가 그렇게 보이는 이유는 획이 **셀 전체를 가로지르는 직선**이라는 점이다.
랜덤 픽셀을 뿌리면 노이즈로 보인다. 5×5 격자에서 "이 행은 가로획", "이 열은 세로획"을
뽑아 통째로 채우면 田·目·王·書 같은 밀도가 나오고, 일부에 바깥 테두리를 주면
国·回 계열이 섞인다.

### 빛 웅덩이 — 왜 필요한가

야간 씬의 빛은 대부분 emissive 표면인데, 발광 표면은 래스터라이저에서 주변을 밝히지
않는다. 그래서 간판은 빛나는데 그 아래 노면은 새카맣다. **첫 렌더에서 도로가 완전히
검게 나온 원인이다.**

광원을 늘려서 해결할 수 없다. 가로등만 150개고, Unity Built-in 포워드 렌더링은
오브젝트당 픽셀 광원이 4개다. 게다가 지오메트리를 큰 메시 몇 개로 병합했으므로
"오브젝트당 4개"가 사실상 "씬 전체에 4개"가 된다.

그래서 빛을 계산하지 않고 **그린다**. 방사형 감쇠 텍스처를 가산합성으로 깔면 젖은
노면에 빛이 고인 것처럼 보인다. 웅덩이마다 색이 다르므로 색을 **정점**에 실어 수백 개를
드로우콜 하나로 유지한다.

## 2. 저장된 씬

씬은 지우지 않고 쌓는다 (`scenes/index.js` 의 `SAVED`). 활성 씬은 마지막 항목이고,
`?scene=<id>` 로 아무거나 다시 띄울 수 있다.

### 씬 1 — `vacant-lot` 주택가 공터 (낮, 3인칭)

기준 씬이다. 좌표계·조명 규약을 실측으로 확정했고 파이프라인 79항목이 여기서 통과했다.
삼각형 182,428 / 텍스처 73장(63MB) / 재질 45개 / 충돌체 14개.

| 모듈 | 내용 |
|---|---|
| `terrain.js` | `LOT` 경계, `groundHeight` / `surfaceHeight`, 지면(96,800삼각형) · 도로 |
| `structures.js` | 담장, 주택 9채, 전신주·전선 |
| `scatter.js` | 잡초 7,200포기 — 잎 1장 인스턴싱 + 노이즈 밀도 |
| `props.js` | 블록·벽돌 무더기, 타이어, 드럼통, 잡석 300개, 표지판, 관목 |
| `textures.js` | 흙·아스팔트·벽돌·시멘트블록·도장벽·칼라강판·녹 |
| `materials.js` | `texMaterial`(텍스처 클론 + repeat), `buildMaterials` |
| `env.js` | 하늘돔, 태양·반구광·채움광 |

`surfaceHeight` 가 지형·아스팔트·경계석 높이를 분리한다. 지형 높이만 쓰면 캐릭터가
도로에 10cm 잠긴 채 걷는다.

주택은 크기가 제각각이라 텍스처를 공유하면 벽돌 크기가 달라진다. `texture.clone()` 으로
**픽셀 데이터는 공유하고 repeat만 다르게** 잡는다 — 클론이 캔버스를 복사하지 않으니 공짜다.

### 씬 2 — `night-city` 나이트시티 (야간 도시, 프리캠 전용)

삼각형 3,644,044 / 텍스처 285장(218MB) / 재질 188개 / 메시 56개.
건물 306동 · 간판 1,617장 · 사람 4,995명 · 주차 947대 · 가로시설 497개.
`meta.player:false` 이므로 캐릭터·물리·충돌체를 만들지 않는다.

모듈이 40개다 (공터는 8개). 아래 표는 뼈대만 적는다 — 전체 목록과 생성 순서는
`docs/scenes/night-city/generation.md` 1절에 있다.

| 모듈 | 내용 |
|---|---|
| `layout.js` | 격자 치수(블록 66m + 도로 22m), 블록 분할, 높이 분포 |
| `streets.js` | 노면·인도·차선·횡단보도·가로등·신호등 |
| `towers.js` | 포디움 · 세트백 몸통 · 크라운. 간판 요청과 웅덩이 목록을 남긴다 |
| `signage.js` | 요청 목록을 배너·세로 간판·광고판 지오메트리로 |
| `highway.js` | 고가도로 (상판·거더·방음벽·교각) |
| `skyline.js` | 원경 실루엣 링 3겹, 2.4km까지 130동 |
| `traffic.js` | 지상 차량 96대 — InstancedMesh 4개(차체·전조등·후미등·전조등 빛) |
| `air.js` | 공중 차량 26대 |
| `env.js` | 야간 하늘돔, 지수 안개, 달빛 + 반구광 |

**건물이 상자로 보이지 않게 하는 세 가지**: 세트백(계단형 실루엣) · 층 띠(수평 리듬) ·
포디움(가로 스케일). 이 셋이 없으면 창문 텍스처를 아무리 잘 만들어도 격자 무늬 육면체다.

**높이는 균등 난수로 뽑지 않는다.** 나이트시티의 인상은 네온이 아니라 수직 스케일의
격차에서 온다. 저층(8~26m) · 중층(34~90m) · 초고층(130~300m) 세 등급을 확률로 섞고,
도심 코어로 갈수록 높은 등급의 확률을 올린다.

**광원 예산**: 실제 광원은 방향광 1(달) + 반구광 1, 둘뿐이다. 빛나는 것은 전부 emissive
표면이고, 그 빛이 다른 표면에 도는 것은 씬 환경맵과 빛 웅덩이다. 창이 수만 개인 도시를
점광원으로 만들 방법이 없고, 엔진 포워드 렌더링은 오브젝트당 픽셀 광원이 4개다.

**창은 백색, 색은 간판이 만든다.** 창에 채도 높은 색을 5%만 섞어도 화면을 지배해서
도시가 크리스마스트리가 되고 정작 간판 색이 죽는다. 이걸 세 번 조정해서 알아냈다.

### `dynamic/` — 스켈레탈 메시

| 모듈 | 내용 |
|---|---|
| `rig.js` | 본 17개 계층 (유니티 휴머노이드 이름) + rest 월드 행렬 |
| `pose.js` | 포즈 수식 — **실시간과 클립 굽기가 공유** |
| `character.js` | 조각 19개를 본에 리지드 웨이트로 묶어 단일 `SkinnedMesh` |
| `clips.js` | 절차적 포즈를 `AnimationClip` 으로 굽기 (30fps) |

클립 길이는 위상 속도에서 계산으로 나온다: `duration = 2π / (2.1 + speed × 1.35)`

| 클립 | 계산 | GLB | 유니티(FBX) |
|---|---|---|---|
| Walk (3.3 m/s) | 0.958s | 0.959s | 0.958s |
| Run (6.4 m/s) | 0.585s | 0.585s | 0.585s |
| Idle | 4.363s | 4.363s | 4.333s |

`f = frames` 를 `f = 0` 과 같은 위상으로 잡아 루프 이음선을 없앤다.

### `export/gltf.js` — GLB 익스포트

세 가지를 자동으로 처리한다.

1. **하위 `InstancedMesh` 굽기** — 그대로 두면 `EXT_mesh_gpu_instancing`(필수 확장)이
   되고 개체별 색이 유실된다
2. **루트 트랜스폼 초기화** — 물리가 갱신하는 런타임 좌표가 박히면 임포트 측에서
   공중에 뜬다. `finally` 로 복구한다
3. **애니메이션 클립 동봉** — 캐릭터에만 `animations` 를 넘긴다

### `controls.js` — 입력·물리·카메라

WASD·달리기·점프·프리캠(언리얼 에디터식). 지형 충돌은 `surfaceHeight` 로,
구조물 충돌은 원-AABB 밀어내기로 한다. 상수는 `WALK 3.3 / SPRINT 6.4 / GRAVITY 23 /
JUMP_V 7.4 / RADIUS 0.32 / STEP 0.45`.

### 스크린샷 하네스

`window.__shot({ name, pos, target, time })` 이 고정 해상도·고정 카메라·고정 시간으로
한 프레임만 그리고 `gl.readPixels` 로 프레임버퍼를 읽어 서버에 올린다.
`window.__sim(keys, frames)` 는 입력을 코드로 주입해 조작을 검증한다.

**시드 고정이 전제다.** `Math.random()` 을 하나라도 쓰면 두 스크린샷의 차이가 수정
때문인지 난수 때문인지 구분되지 않는다.

## 2. 블렌더 — 파일을 만든다

### `tools/glb-to-fbx.py`

옵션은 전부 `contract_gen.py`(생성됨)에서 온다. 스크립트가 하는 일:

1. GLB 임포트
2. `glTF_not_exported` 컬렉션 제거 (본 표시용 Icosphere)
3. `loose` 모드면 패킹된 이미지를 개별 PNG로 풀어놓기
4. `FBX_OPTIONS` 로 익스포트

**텍스처는 반드시 별도 파일로 내보낸다.** `embed_textures=True` 로 FBX 안에 박으면
파일에는 실제로 들어가지만(`Video` 노드 38개 확인) **유니티가 자동 추출하지 않아
전부 유실된다** — 집이 하얗게 나온다.

### `tools/blender-check.py`

임포트 결과를 계측한다. 삼각형·정점·머티리얼·이미지, 머티리얼 노드 연결 상태
(BaseColor / Roughness / **Normal**), 정점 컬러, 아마추어·본·정점그룹·액션, 크기.

Workbench 렌더로 PNG도 남긴다 (`color_type` 을 텍스처/정점컬러 중에서 자동 선택).

> Blender 4.4+/5.x는 슬롯 액션 구조로 바뀌어 `Action.fcurves` 가 사라졌다.
> `action_curve_count()` 가 레거시와 신규(`layers > strips > channelbags`)를 모두 지원한다.

### `tools/inspect-glb.mjs`

블렌더 없이 GLB 바이너리를 직접 파싱한다. 확장 목록, 노드·메시·머티리얼·이미지 수,
정점 속성, 삼각형 수, 블렌더 임포트 차단 여부.

> 삼각형 수는 **헤더 기준**이라 공유 메시를 과소 계상한다. 엔진에서 실제로 그려지는
> 수는 `PipelineCheck` 가 노드별로 센다 (props: 헤더 4,860 vs 엔진 5,604).

## 3. 유니티 — 임포트하고 검증한다

### `BuildScene.cs` — 씬 조립

정적 8조각을 원점에 얹고(추가 변환 없이 서로 맞는다), 캐릭터는 FBX에서 가져와
`Animator` + `CharacterController` + `PlayerController` 를 배선한다. 콜라이더는
ground/road/walls/houses에만 213개 — 브라우저도 집·담장만 충돌체로 썼다.

환경값은 브라우저 `env.js` 를 그대로 이식하되 **광원 방향의 X를 반전**한다.

정점 컬러를 가진 메시에 전용 머티리얼을 자동 적용한다. 셰이더별 프로퍼티 이름을
가정하지 않고 훑어서 앨비도 텍스처 유무로 판정한다. 잡초는 바람 머티리얼로 덮어쓰고
그림자 캐스팅을 끈다 — 켜두면 72,000 삼각형이 흙바닥을 새카맣게 덮는다.

### `AnimatorSetup.cs` — Animator 컨트롤러

`Speed`(float) 하나로 Idle↔Walk↔Run을 1D 블렌드 트리로 섞고, `Airborne`(bool)로 Air를
오간다. 임계값은 브라우저의 실제 이동 속도(3.3 / 6.4)를 그대로 써서 게임 코드에서
속도를 그대로 꽂으면 케이던스가 맞는다.

검증도 한다 — 에디터 모드에서 `Animator.Update()` 로 60프레임 돌려 팔 스윙 진폭을 측정:
Idle 1.06° / Walk 47.07° / Run 56.01°.

### `PipelineCheck.cs` — 적합성 검사 (단일 진입점)

이전에는 질문 하나에 답하려고 즉석에서 만든 진단 스크립트가 9개 흩어져 있었다.
서로를 모르니 "지금 파이프라인이 건강한가?"에 한 번에 답할 수 없었다.
지금은 4단계 49항목을 검사하고 실패 시 종료 코드 1로 알린다.

### 셰이더

| 셰이더 | 역할 |
|---|---|
| `AcesTonemap` | three.js `ACESFilmicToneMapping` 을 상수·행렬 그대로 포팅 |
| `GradientSky` | 브라우저와 같은 5스톱 그라디언트 스카이박스 |
| `VertexColorLit` | 정점 컬러를 알베도에 곱함 (잡석) |
| `VertexColorWind` | 정점 컬러 + 바람 흔들림 (잡초) |

**바람 셰이더의 이식 문제**: 브라우저는 위상을 `instanceMatrix` 에서 뽑았는데 유니티
쪽은 이미 구워진 단일 메시라 그게 없다. 대신 잎 높이는 `uv.y`(blade geometry가
`uv=(0|1, t)` 로 만든다), 포기별 위상은 정점의 월드 XZ로 만든다.

시간은 `_Time.y` 가 아니라 전역 `_WindTime` 을 쓴다. 배치 렌더에서 시간을 고정해 두
프레임을 비교 검증해야 하기 때문이다. 브라우저도 `uTime` 유니폼을 쓰는 같은 구조다.

> 검증: `_WindTime` 을 0 / 0.35 / 0.70 / 1.05로 고정해 렌더하고 픽셀 차이를 측정.
> 공터(잡초) 4.75 → 6.95 / 255, **도로(대조군) 0.00** — 잡초만 움직인다.

**색공간 함정**: Linear 색공간에서는 유니티가 머티리얼 `Color` 프로퍼티를 셰이더로
넘기기 전에 **이미 선형 변환**한다. 셰이더에서 `GammaToLinearSpace()` 를 또 부르면
이중 선형화가 되어 어둡고 과채도가 된다 (하늘 실측 −83, −62, −30).

### `PlayerController.cs` — 런타임 조작

`controls.js` 를 옮긴 것으로 상수도 그쪽 값을 그대로 쓴다. 지형 충돌은 절차적 높이
함수를 옮기는 대신 유니티 물리(`CharacterController` + `MeshCollider`)에 맡긴다 —
엔진에 넣는 게 목적이므로 엔진 방식이 맞다.

`Animator` 파라미터를 매 프레임 갱신한다:

```csharp
animator.SetFloat("Speed", horizontalSpeed);
animator.SetBool("Airborne", !_cc.isGrounded);
```

`modelYaw` 는 씬 조립 시점에 규약에서 주입받는다 — 런타임 코드가 좌표계 규약을
직접 알지 않는다.
