# 게임 프로젝트 계획 — 파이프라인과 게임을 가르는 선

이 저장소는 **에셋 공장 + 검증 장비**다. 실제 게임(크래프팅·서바이벌·어드벤처,
story.md)은 **별도 유니티 프로젝트**에서 만든다 (2026-08-05 사용자 결정).
이 문서는 그 분리의 근거, 두 프로젝트 사이의 계약, 그리고 게임 쪽 작업의
단계 계획이다.

---

## 1. 왜 분리하나

**이 저장소의 `unity/` 는 게임이 아니라 계측기다.** `BuildOfficeScene.Full` 은
배치모드로 씬을 **지웠다 다시 조립**하고, 적합성 검사를 돌리고, 스크린샷을
남기는 장비다. 게임 코드가 같은 프로젝트에 살면:

| 충돌 | 무엇이 깨지나 |
|---|---|
| 씬 재조립 | 파이프라인이 돌 때마다 게임 씬 작업이 덮인다 |
| 패키지 오염 | 인풋·네트워킹·UI 패키지가 검증 프로젝트의 재현성을 흔든다 |
| 커밋 리듬 | 여기는 "에셋이 규약을 지키는가", 게임은 "재미있는가" — 역사가 섞이면 둘 다 못 읽는다 |

```
Meshpipeline (이 저장소)               게임 프로젝트 (신규 저장소)
브라우저 = 에셋 공장 + 기준(reference)  게임플레이 전부
unity/  = 검증 장비 (검사·뷰포트 확인)   상호작용·인트로·크래프팅·멀티
        │
        └── 납품물 ──────────────────▶  검증을 통과한 것만 넘어간다
```

## 2. 납품물 — 두 프로젝트 사이의 계약

**파이프라인 통과(`node tools/pipeline.mjs office-sector` 종료 코드 0)가 납품
조건이다.** 넘어가는 것은 넷.

### 2.1 GLB 9종

`unity/Assets/ProceduralImport/office/` 에 파이프라인이 복사해 둔 그대로.

```
rock · floors · walls · ceilings · props · fixtures      배경 (병합)
interactables          상호작용 소품 — 물건마다 개별 노드 (rack_07 등)
interactables_open     약탈 뒤 열림 포즈 (rack_07_open) — 루트 비활성으로 임포트
startroom_pre          시작 방의 지진 전 상태 (닫힌 문짝) — 루트 비활성
```

### 2.2 셰이더 둘

| 셰이더 | 왜 필수인가 |
|---|---|
| `Custom/BakedVertexColor` | 조명이 정점에 구워져 있다 — 유니티 광원 0개로 브라우저와 같은 화면을 내는 핵심. 크랙 오버레이는 **이 셰이더를 확장**해서 만든다 (status.md 5.2) |
| `AcesTonemapper` | 브라우저의 ACES 톤매핑 대응물. 노출 1.05 |

### 2.3 규약 상수 — `PipelineContract.g.cs`

좌표 변환(glTF→유니티 X 반전), `modelYaw`, `useFileScale` 등 실측으로 확정한
값들. **게임 코드에 숫자를 다시 적지 않는다** — 이 파일을 그대로 가져간다.
(원본은 `pipeline/contract.json`, 손대지 말고 재생성으로만.)

### 2.4 이름 규약 — 게임 로직이 물건을 찾는 방법

이름은 생성기가 결정론으로 보장한다 (core/material.js · props.js interactSet).

| 이름 | 게임이 하는 일 |
|---|---|
| `rack_07` / `rack_07_open` | 약탈 시 닫힘 끄고 열림 켜기 (1프레임 스왑) |
| `rubble_01` · `startroom_pre` | **인트로 공식**: 인트로 동안 = 씬 − rubble_01 + startroom_pre. 기절 암전에서 반대로 스왑 |
| 재질 `Fluoro`·`ExitSign`·`Glass` 등 | 발광·유리 판별 (BuildOfficeScene.KeepByName 과 같은 목록) |

> **세이브 경고** (scenes/office-sector/status.md 1장): `rack_07` 의 번호는
> 생성 **순서**에서 나온다. 평면·밀도를 바꾸면 번호가 통째로 밀린다.
> **세이브가 이 이름으로 상태를 저장하기 시작하기 전에** 배치를 동결하거나,
> 좌표 해시 기반 안정 ID 를 납품물에 추가해야 한다.

## 3. 납품 절차

### 지금 (수동 복사 — 1단계면 충분)

```
1. 브라우저에서 확정  ->  __export 9종
2. node tools/pipeline.mjs office-sector    (통과해야 납품)
3. 게임 프로젝트로 복사:
     unity/Assets/ProceduralImport/office/*.glb
     unity/Assets/Shaders/ (BakedVertexColor 등)
     unity/Assets/Editor/PipelineContract.g.cs
```

이름이 결정론이라 **재복사 = 갱신**이고, 겹쳐 써도 안전하다.
복사 스크립트(`tools/deliver.mjs` 같은 것)는 게임 프로젝트가 생기면 그때
경로를 받아 만든다 — 지금 만들면 목적지가 상상 속이다.

### 나중에 (필요해지면)

복사가 귀찮아지는 시점에 UPM 로컬 패키지(`com.<이름>.office-assets`)로
승격한다. 그 전까지는 안 한다 — 소비자가 하나뿐인 추상화는 비용만 있다.

## 4. 게임 프로젝트 초기 설정

| 항목 | 값 | 왜 |
|---|---|---|
| 유니티 버전 | **6000.3.11f1** (검증 장비와 동일) | 버전이 갈리면 검증이 보증하는 것이 없어진다 |
| 렌더 파이프라인 | **Built-in** | 현 셰이더 둘이 Built-in 기준이다. URP 전환은 셰이더 이식을 각오한 별도 결정 |
| glTF 임포터 | glTFast (unity/Packages 와 동일 버전) | GLB 를 읽는 주체. 노드 계층·정점 컬러 보존 실측 완료 |
| 색공간 | Linear | 정점 컬러 굽기의 전제 |
| 임포트 후 재질 교체 | BuildOfficeScene.cs 의 재질 교체 로직을 게임 쪽 에디터 스크립트로 이식 | 이름 캐시 · 베이스컬러 팩터 복사 · KeepByName — 전부 실측으로 얻은 규칙이다 |

## 5. 단계 계획

| # | 단계 | 내용 | 완료 기준 |
|---|---|---|---|
| 0 | 납품 1회차 | 게임 저장소 생성 · 3장 절차로 GLB·셰이더·상수 반입 · 씬 조립 스크립트 이식 | 게임 프로젝트 뷰포트가 검증 장비의 `Reports/office_scene.png` 와 같아 보인다 |
| 1 | 이동 | 1인칭 컨트롤러 · 콜라이더 (개별 노드는 메시 콜라이더, 병합 배경은 벽·바닥 기준) | 층 전체를 걸어서 돈다. 잔해 문이 실제로 막는다 |
| 2 | 상호작용 | E 근접 상호작용 (브라우저 프리뷰와 같은 반경 2.4m 규약) · 약탈 토글 · 인벤토리 최소 | 캐비닛을 열면 아이템을 얻고 열림 포즈가 남는다 |
| 3 | 인트로 | 전 상태로 시작 → 지진 연출(카메라 흔들림 + 암전) → 후 상태 스왑 → 깨어남 | 인트로 공식(2.4)이 그대로 돈다 |
| 4 | 파괴 | 크랙 셰이더(BakedVertexColor 확장) · 타격 → 크랙 단계 → 파괴 → 부품 드롭 | 소품을 부수면 부품이 나온다 |
| 5 | 탈출 | 덕트 진입 → washN → 건물 밖 (씬 경계) | 스토리 2장의 오프닝 시퀀스가 처음부터 끝까지 플레이된다 |
| — | 멀티 (B·C·D) | 위가 싱글로 완성된 뒤 | 별도 계획 |

에셋 쪽 선행 작업과의 맞물림: 4단계 전에 **파손·정전 연출**(층 전체),
5단계 전에 **덕트 탈출 루트 지오메트리** — 둘 다 이 저장소의 백로그다
(scenes/office-sector/status.md 5.2).

## 6. 지키는 원칙

1. **게임 프로젝트에서 에셋을 직접 고치지 않는다.** 수정은 항상 브라우저
   코드 → 파이프라인 → 재납품. "브라우저가 기준" 이 게임까지 이어지는 선이다.
2. **납품은 파이프라인 통과본만.** 검사 안 거친 GLB 가 게임에 들어가는 순간
   "브라우저와 같아 보인다" 는 보증이 끊긴다.
3. **규약 값은 contract.json 이 유일한 출처.** 게임 코드가 좌표 보정 숫자를
   따로 적기 시작하면 이 저장소가 가장 크게 데인 결함(값의 이중화)을
   게임에서 반복하게 된다.

## 7. 아직 정하지 않은 것

| | 정할 시점 |
|---|---|
| 게임 저장소 이름·구조 | 0단계 시작할 때 |
| 안정 ID (좌표 해시) 납품 여부 | 세이브 시스템 설계 전 — 배치 동결이 먼저면 불필요 |
| URP 전환 여부 | 비주얼 요구가 Built-in 한계에 닿을 때. 셰이더 2종 이식 비용과 함께 결정 |
| 캐릭터(다이나믹) 납품 | B·C·D 가 필요해질 때 — vacant-lot 의 FBX 경로(휴머노이드 아바타)가 출처다 |
